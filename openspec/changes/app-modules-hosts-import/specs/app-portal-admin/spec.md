## MODIFIED Requirements

### Requirement: 新增应用
管理后台 SHALL 支持新增应用，提交表单后保存到 LiteDB 并跳转回管理列表。表单支持配置模块及模块下入口，至少配置一个入口。

#### Scenario: 打开新增表单
- **WHEN** 用户点击"新增应用"按钮
- **THEN** 导航到 `/Admin/Create`，显示空表单（含默认一个模块及一行入口）

#### Scenario: 成功新增应用（最少字段）
- **WHEN** 用户填写了应用名称和至少一个模块下的一个有效入口（Http 需完整 URL 或可拼装的端口，或 UrlOverride）
- **THEN** 系统创建应用并跳转到管理列表
- **THEN** 新应用出现在列表中，默认状态为启用

#### Scenario: 新增时验证必填字段
- **WHEN** 用户提交表单时名称为空或没有任何有效入口
- **THEN** 系统显示验证错误信息，不保存数据
- **THEN** 页面保持当前表单，用户输入不丢失

#### Scenario: 新增时配置多个模块
- **WHEN** 用户添加了多个模块并在各模块下配置入口
- **THEN** 提交后模块与入口均保存到该应用

### Requirement: 编辑应用
管理后台 SHALL 支持编辑已有应用的信息，包括名称、描述、图标地址、模块列表（含入口、排序、启用状态）、HostRefs 和排序。

#### Scenario: 打开编辑表单
- **WHEN** 用户点击某个应用的"编辑"按钮
- **THEN** 导航到 `/Admin/Edit/{id}`，表单预填当前值（模块与入口）

#### Scenario: 成功编辑应用
- **WHEN** 用户修改了应用信息并提交
- **THEN** 系统更新该应用并跳转到管理列表
- **THEN** 更新后的信息生效

#### Scenario: 编辑时调整模块与入口
- **WHEN** 用户在编辑时删除某些入口行、新增模块或修改模块 IsEnabled
- **THEN** 提交后模块/入口结构更新为修改后的值

### Requirement: 管理表单动态地址行
新增和编辑表单 SHALL 支持通过 JavaScript 动态添加/删除模块行及模块下的入口行。

#### Scenario: 添加入口行
- **WHEN** 用户点击某模块的"添加入口"按钮
- **THEN** 该模块下新增一行入口编辑区（显示名、类型、端口/URL 等）

#### Scenario: 删除入口行
- **WHEN** 用户点击某入口行的"删除"按钮
- **THEN** 该行从表单中移除，提交时该行数据不被提交

#### Scenario: 添加与删除模块
- **WHEN** 用户添加或删除模块块
- **THEN** 对应模块及其入口随表单提交更新
